# Plan — MA tab

- `scripts/build-ma-progress.mjs` (Node ≥18, built-in `fetch`, no dependency): exports
  `buildMaProgress({ fetchJson, now })` (pure, testable) and a CLI that wires the real Qase fetch.
  Pages: `/suite/MA`, `/case/MA`, `/run/MA?status=complete&include=cases`, `/result/MA?run=<id>`, 100 per page.
  Writes `public/ma-progress.json` via a temp file + rename (R9).
- `scripts/build-ma-progress.test.mjs`: `node --test`, mocked `fetchJson`; known answers for R5–R8 and a
  check that the token never reaches stdout/stderr (R4).
- `public/index.html`: remove the three hidden tab buttons (R1), add `.tab[data-view="ma"]` first with
  `active`, default `activeView = 'ma'`, `renderView()` branch → `renderMa()` that fetches
  `/ma-progress.json` (no-store) and reuses the OLS classes (`.ols-cards`, `.ols-pct`, `.ols-note`,
  `animateOls`). The `ma` view uses a 3-column card grid.
- `public/ma-progress.json`: generated by main before deploy; never hand-edited.
- Cost: none (free Qase API already used, no new service or package). Other repos touched: none.
- Risk: `fetchAndRender()` (old Qase loader) replaces `#content` on error — guarded so it only does that
  when a hidden view is active. The JSON is public; it carries counts, run titles and timestamps only.

## Plan — total cases per system (R19–R22, owner order 2026-10-22)

- `scripts/build-ma-progress.mjs`: `totalCases = own.length` (cases already collected for R6); guard
  `totalAutomated <= totalCases` → throw (R9 keeps the old JSON).
- `scripts/build-ma-progress.test.mjs`: known answers updated for the new field; a mixed-automation suite
  proves `totalCases` counts automation 0/1/2 alike.
- `public/index.html`: `maValid()` requires numeric `totalCases` and `totalAutomated <= totalCases`;
  `renderMa()` adds the "Total cases" card first; `.ols-cards.ma-cards` grid 4 / 2 / 1 columns.
- `public/ma-progress.json`: regenerated by the builder.
- Cost: none. Other repos: none. Risk: the old JSON on production lacks `totalCases` — deploy the new
  JSON and page together (same `public/` upload), never the page alone.
- Deploy: production only (owner 2026-10-28) — `wrangler pages deploy public/ --project-name
  mica-automate-coverage --branch main`, then verify on the production URL.

## Plan — live data in the browser (R23–R27, owner order 2026-10-28)

- `public/ma-progress-core.mjs` (new): `buildMaProgress({ fetchJson, now })` moved here unchanged except
  `fetchAll` — first page, then the rest with `Promise.all`, results kept in offset order (R25).
- `scripts/build-ma-progress.mjs`: imports and re-exports `buildMaProgress` from the core; CLI unchanged (R24).
  Existing tests keep importing from the builder and must pass untouched.
- `public/index.html` `renderMa()`: dynamic `import('/ma-progress-core.mjs')`, `fetchJson = path =>
  fetch('/api/qase' + path)`, loading message, then the same `maValid()` + render. Error text no longer says
  "regenerate and deploy" (R27).
- `public/ma-progress.json`: no longer read by the page; left in place (removal is a separate decision).
- Weighed: Pages Function + cache (over free-plan CPU 10 ms / 50 subrequests — measured 19.3 ms parse,
  33+ subrequests and growing); GitHub Actions daily build + deploy (needs two new secrets, up to 1 day stale).
- Cost: none — same proxy, about 35 proxy calls per open (free plan 100,000 requests/day). Other repos: none.
- Risk: opening the tab costs ~3–5 s of loading (measured 3.4 s for 31 parallel pages from Node). The proxy's
  hardcoded Qase token is a separate, pre-existing security issue — not changed here.
